# チューン形式の候補を絞り込む方法の検討（2026-10-26）

動き検討ツール（move-estimate-tool.html）のチューン形式で、候補が多く出る人の候補を減らす方法を検討した記録。
実装はまだしていない。次に決めることは末尾の「未決事項」を見る。

## 前提（2026-10-26 時点の定数）

- 貯め: 525pt・トリガー +525（同日に 595 → 525 へ修正済み）
- 吐き: 637pt・トリガー −140
- ボーナス: 3,000pt。ツールは0回か5回として計算する
- トリガー数の範囲: −10,000〜999,999
- 同じptの候補どうしは「貯め91回 ⇔ 吐き75回」の置き換えだけが違う（525×91 = 637×75 = 47,775）。
  トリガー数の差は 58,275
- このため、ある期間に増えたptが 47,775 未満なら、その期間の貯め・吐き・ボーナスの回数は1通りに決まる

## 運用上の問題

- ボーナス0回の人は、「ボーナス0回なら吐き0回」の規則（`zeroRelease`）で主な候補が1件になる
- ボーナス5回の人は、主な候補が12〜13件出る（pt 70万台）。運用上の問題はここ
- 今のツールで候補が0件になる人は、運用上は重要でない（ユーザー判断）

## 検討1: 24時間の増加量（1点）を与える案 → 効果がほぼ無い

24時間前のpt（現在pt − 24時間の増加量）にも成り立つ回数の組があり、その組の回数がすべて今の候補以下であれば、その候補を残す。この条件で絞った。

- 総当たり（現在pt 4通り × 増加量 1〜800,000）では、減ったのは最大1〜2件。減ったのは増加量全体の0〜12%だった
- 実データ（下表）でも、ボーナス5回の4人で減ったのは0〜1件。消えたのは吐き回数が最も少ない1件だけ
- 理由: どの候補も貯め・吐きが数百回以上あるので、回数がすべて今以下の24時間前の組がほぼ必ず見つかる

## 検討2: 複数時点のptを与える案 → 1区間の増加が小さければ1件に決まる

イベント開始時（0pt・全回数0）から時刻順に、前の時点の候補のどれかから回数を減らさずに進める候補だけを残していく。

使った動きは乱数で作った（ボーナス5回、84時間、30分あたり約4,600pt、198通り）。結果は次のとおり。

| ptを与える間隔 | 1区間の増加（目安） | 残った候補（平均） | 最大 | 1件に決まった割合 |
|---|---|---|---|---|
| なし（今のツール） | — | 13.7 | — | — |
| 12時間 | 約11万pt | 9.6 | 13 | 0% |
| 6時間 | 約5.5万pt | 1.7 | 5 | 58% |
| 3時間以下 | 約2.8万pt以下 | 1.0 | 1 | 100% |

- 本当の回数が候補から消えたことは1回も無い
- 効果を決めるのは時間でなく、1区間で増えたpt。47,775pt 未満の区間が多いほど候補が減る。時刻は不揃いでよい
- 開始時の0ptから最初の1点までも1区間に数える。最初の1点が遅い（ptが大きい）と、その区間で候補が残る
- 1点でも打ち間違えると、本当の候補が消えるか0件になる

## 再現方法

検証スクリプトは作業用の一時フォルダに置いたため、残っていない。要点だけ記す。
`tests/helpers/load-move.js` の `loadMove()` でツールの `solve` と `FORMATS` を読む。

```js
const { loadMove } = require('./tests/helpers/load-move');
const mv = loadMove();
const U = mv.FORMATS.tune;
// 途中の時点はボーナス0〜5回を許す
const any = { ...U, bonus: { ...U.bonus, counts: [0, 1, 2, 3, 4, 5] } };
const le = (x, y) => x.charge <= y.charge && x.release <= y.release && x.bonus <= y.bonus;

// pts: 時刻順の累計pt（最後が現在）。開始時の0ptから順につなぐ
function chain(pts) {
  let reach = [{ charge: 0, release: 0, bonus: 0 }];
  pts.forEach((pt, i) => {
    const f = i === pts.length - 1 ? U : any;
    reach = mv.solve(pt, f).filter(s => reach.some(r => le(r, s)));
  });
  return reach;
}
```

- 検討1は `chain([現在pt − 24時間の増加量, 現在pt])` と同じ結果になる（開始時の0ptからは、24時間前のどの候補へも進めるため）
- シミュレーションの動き: 30分ごとに0〜16回の動きを打つ。吐きはトリガーが −10,000 を下回らない範囲で確率 0.45〜0.65、それ以外は貯め。ボーナス5回は84時間のどこかにランダムに入れる
- 時点の間の途中でトリガー数が範囲を外れないかは検査していない（各時点のトリガー数が範囲内であることだけを見ている）

## 未決事項

- 時点の値が矛盾して0件になったときの知らせ方
